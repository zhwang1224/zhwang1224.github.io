NVIDIA Groq 3 LPU：用确定性执行加速交互式 AI 推理

发表于 2026-09-01 更新于 2026-09-02 分类于 计算机体系结构 ， 人工智能系统 阅读时长 ≈ 10 分钟
总结 Groq 3 LPU 的全 SRAM、周期级调度、同步互连及其在异构推理中的作用。

NVIDIA 在 Hot Chips 2026 展示的 Groq 3 LPU，目标并不是取代 GPU，而是补上 GPU 系统在交互式推理中的另一条轴：GPU 擅长用大批量获得高吞吐，LPU 则用确定性执行换取低而稳定的单用户延迟。在 NVIDIA 的 Vera Rubin 平台中，两者被组合成异构推理系统，让不同阶段落到更合适的硬件上。

LPU 的关键并非某一个矩阵单元，而是一整套协同设计：权重与中间数据尽量留在片上 SRAM，编译器按时钟周期安排计算和通信，多颗芯片共享虚拟全局时钟。由此，模型执行从“运行时不断等待和仲裁”变成一张提前排好的时间表，LPU 也就能以可预测的节奏连续生成 Token。

NVIDIA Groq 3 LPU：用确定性执行加速交互式 AI 推理

一、LPU 要解决什么问题

智能体工作负载会把提示、模型输出和工具调用结果不断追加到上下文中。会话轮次越多，KV Cache 越大，后续推理延迟也越容易累积。对于面向用户的服务，仅提高整个机房每秒处理的 Token 数并不够，还要提高单个用户实际感受到的生成速度，即 TPS/User。

这正是 LPU 与 GPU 的定位差异：GPU 依靠并行度和批处理提高 TPS/MW，适合吞吐优先的任务；LPU 把工作负载变成确定性的计算与通信流水线，面向小 Batch、延迟敏感的 decode。二者组合的目的，是同时扩大吞吐与交互性，而不是让一种芯片包办所有阶段。

图 1：将 GPU 放在高吞吐一侧、LPU 放在极低延迟一侧，异构组合则用于兼顾两项目标。

二、LPU 如何获得确定性低延迟

2.1 用片上 SRAM 缩短数据路径

Groq 3 LPU 采用扁平内存层次，工作数据全部放在片上 SRAM，并通过高带宽 Stream 向计算单元供数。核心中的主要功能单元包括：

  • MEM：片上 SRAM 及其读写路径；
  • VXM：向量处理单元；
  • MXM：由乘加单元组成的矩阵计算阵列；
  • SXM：负责移位、重排等数据变换。

这项选择绕开了多级缓存命中、片外 DRAM 访问和运行时搬运带来的不确定等待。代价也很明确：SRAM 的容量不如 DRAM/HBM，软件必须更严格地规划模型切分、数据放置和生命周期。因此，LPU 更适合容纳延迟关键的工作集，而长上下文 KV 等大容量状态仍可交给 GPU 一侧的 DRAM。

图 2：MEM、VXM、MXM 和 SXM 由高带宽 Stream 串成数据流，控制逻辑只占较小面积。

2.2 把运行时调度移到编译期

LPU 使用 VLIW 风格架构，由软件以时钟周期为粒度安排 SRAM 读写、算术运算和数据传输。PPT 中的简单例子把两次读取、一次加法、结果上流和写回精确放到第 0、2、3、5、7 周期；独立操作可以同时占用不同单元，连续算子之间也不需要经过 kernel 边界或 MEMBAR，因而能够直接融合成更长的流水线。

它带来的作用不是让每条指令本身更复杂，而是减少运行时仲裁和同步：编译器提前知道某个张量在何时到达、哪个单元在何时空闲，执行时间和资源利用率因而可以预测。静态调度也不等于程序不能分支；Groq 3 允许在若干具有确定时间上界的基本块之间，根据数据选择不同路径。

2.3 把多颗芯片排进同一张时间表

LPU 的确定性从芯片内部延伸到机架。系统让机架内乃至跨机架的 LPU 工作在同一个虚拟全局时钟下，并对芯片间时钟漂移做确定性补偿。每颗 LPU 同时充当处理器与路由器，编译器把消息传输和计算一起排进程序，因此网络不需要依赖自适应路由或拥塞感知来临场决策。

这种网络传输的是已知时间、已知大小的张量，而不是不可预测的通用流量。协议只保留很低的头尾开销，也省去硬件流控和虚拟通道信息，对推理中的小张量尤其有利。其成立前提同样是通信模式能够被编译器掌握；它并不是为任意突发网络负载设计的通用替代品。

一个 Groq 3 LPX 机架包含 256 颗 LPU，PPT 给出的汇总规格为 128 GB SRAM、315 PFLOPS FP8、40 PB/s 聚合 SRAM 带宽，以及从一颗芯片 SRAM 到另一颗芯片 SRAM 的 350 ns 延迟。系统还能继续扩展到 1,000 颗以上 LPU。

图 3：256 颗 LPU 通过低延迟互连组成 LPX 机架，并以聚合 SRAM 带宽持续为计算单元供数。

三、LPU 在异构推理中的三种作用

3.1 为推测解码生成草稿

第一种模式是外部 Drafter 推测解码。LPX 上的小模型以低延迟提前生成一批候选 Token，Vera Rubin NVL72 上的大目标模型负责验证、接受并提交结果。两个机架各自保存本模型的 KV Cache，链路上主要传递候选 Token 和被拒绝的位置，而不需要持续搬运两套模型状态。

这里 LPU 的作用是让“串行起草”尽可能快，GPU 的作用则是高效完成大模型验证。通过按块交接并让下一轮起草与验证形成流水，系统可以提高目标模型的利用率，同时缩短用户等待时间。

图 4：LPX 运行小型草稿模型，Vera Rubin 运行大型目标模型，跨机架只传递草稿与反馈。

3.2 把 Attention 与 FFN 分给不同架构

第二种模式在 decode 内部进一步拆分：GPU 计算长上下文 Attention，并利用 DRAM 保存容量持续增长的 KV Cache；LPU 把 FFN 权重放进 SRAM，以低延迟执行前馈层。二者每经过一个完整 Attention 层交换一次中间张量。

这个划分利用了两类算子的差异。Attention 对长上下文状态容量和访问更敏感，GPU 的大容量内存更合适；FFN 更容易形成规则、可静态编排的矩阵流水，LPU 的 SRAM 带宽和确定性调度更容易发挥作用。

图 5：GPU 保存 KV Cache 并执行 Attention，LPU 保存权重并执行 FFN，层间只交换中间结果。

3.3 拆分 Prefill 与 Decode

第三种模式按推理阶段拆分。Vera Rubin 负责长上下文 Prefill 和 KV Cache，LPX 负责对延迟最敏感的 Decode；两侧以“每轮一次”的方式交接 KV 状态。这样既保留 GPU 处理大上下文和高并行计算的能力，又把逐 Token 生成放到低延迟流水线上。

PPT 还提出让 GPU 与 LPU 的计算、双向传输相互重叠，避免异构拆分把收益消耗在等待上。因此，LPU 真正的系统作用不是单独跑出一个峰值数字，而是成为 GPU 流水线中的低延迟阶段。

图 6：Vera Rubin 完成长上下文 Prefill，LPX 接手 Decode，把容量需求与交互延迟分别交给更合适的硬件。

四、确定性还带来了什么

周期精确的执行计划也能反过来帮助供电和散热。硬件可以在负载到达前向稳压器预订电流，PPT 称这种 Pre-Emptive Power 机制使电压下冲减少超过 60%、过冲减少超过 70%。编译器还可以按计算块分配功耗，让原本温度较低的区域提高利用率，而不是因为最热点而对整颗芯片统一降频。

另一方面，真实服务并不完全确定。Groq 3 因而在 LPU 同步域外保留 FPGA Runtime Orchestrator 和 Host 控制平面：主机负责系统软件、DRAM 访问、LPU—GPU 连接和任务提交，进入 LPU 的延迟关键工作集才接受周期精确调度。这道异步桥把动态服务控制与确定性数据面分开，是 LPU 能进入完整 AI 系统的重要条件。

软件生态仍处于扩展阶段。PPT 把 CUDA 对 LPU 的完整支持列为未来方向，规划让 cuTile、CUTLASS、LPU-DSL、Dynamo 和 NVIDIA 加速库共同面向 GPU 与 LPU；LPU 侧则继续使用离线流程完成模型导入、布局向量化、多芯片切分、指令映射、缓冲区分配和调度。

五、如何理解性能数字

NVIDIA 给出的单机架结果包括：Groq 3 LPX 在 Gemma 4 31B 编码基准中达到 11,000 Token/s；第三方 Artificial Analysis 的 100K 上下文测试中，将其标为 4 倍领先。

在 GPT-OSS-2T、缓存输入 400K Token、新输入 4K Token、输出 400 Token 的系统分析中，演相对 Vera Rubin 基线分别给外部 Drafter、Attention/FFN 拆分、Prefill/Decode 拆分标出约 3×、3× 和 5× 的交互性提升。三个点对应不同的 TPS/MW 与 TPS/User 位置，并不是在完全相同吞吐约束下得到的单一加速比。这里真正要表达的是：上下文越长，按阶段和算子选择 GPU 或 LPU，越有机会向外移动整个推理系统的延迟—能效帕累托前沿。

六、总结

LPU 的核心作用可以归纳为一句话：把规则、延迟敏感的推理部分编译成跨芯片的确定性流水线，为 GPU 系统提供更快的逐 Token 生成路径。

为此，Groq 3 LPU 做了三件关键的事：用片上 SRAM 和 Stream 缩短数据路径，用周期级软件调度消除运行时不确定性，再把相同的时间模型扩展到机架网络。进入 Vera Rubin 异构系统后，它可以承担草稿生成、FFN 或 Decode；GPU 则继续处理大模型验证、长上下文 Attention 与 Prefill。

这也说明了 LPU 的边界：它以容量、通用性和部分运行时灵活性换取确定性低延迟。NVIDIA 的方案并不是在 GPU 与 LPU 之间二选一，而是把二者组织成同一条流水线——GPU 负责把工作做大，LPU 负责把关键路径做快。
