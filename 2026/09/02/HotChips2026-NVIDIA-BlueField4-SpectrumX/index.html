英伟达 BlueField-4 与 Spectrum-X：AI Factory 的基础设施与多平面网络

发表于 2026-09-02 分类于 人工智能系统 ， 数据中心网络 阅读时长 ≈ 12 分钟
英伟达如何用 BlueField-4 隔离并接管网络、存储与安全数据路径，再用 Spectrum-X 多平面网络把 AI Factory 扩展到数十万块 GPU。

英伟达正在把 AI Factory 的设计边界从 GPU 计算扩展到整套数据中心基础设施。BlueField-4 位于服务器与数据中心共享资源之间，独立执行网络、存储、安全和遥测；Spectrum-X 则用多轨、多平面的以太网拓扑，将低抖动 RDMA 网络扩展到数十万块 GPU。

两者解决的是同一条数据路径上的不同问题：BlueField-4 决定流量能否安全、高效地离开计算节点，Spectrum-X 决定这些流量能否在大规模集群中稳定到达。 这种分工让 CPU 和 GPU 聚焦租户工作负载，同时把基础设施控制权保留在独立的可信域中。

英伟达 BlueField-4 与 Spectrum-X：AI Factory 的基础设施与多平面网络

一、AI Factory 不再只需要一张网络

英伟达把 AI Factory 的互连拆成五个面向不同距离和流量特征的网络，而不是用一张通用以太网覆盖所有场景：

网络维度 连接对象 主要技术 主要作用
Scale-In 计算节点与存储、安全、云服务及管理系统 BlueField-4 隔离租户与基础设施，承载服务访问
Scale-Up 同一计算域内的 GPU NVLink 提供高带宽、低延迟的 GPU 互连
Scale-Out 多个计算域或机架 Spectrum-X 承载训练和推理的 RDMA 通信
Scale-Across 多座 AI Factory Spectrum-XGS 支持跨园区、跨地域分布式计算
Context Scale HBM、系统内存与共享存储 BlueField Storage Processor 扩展智能体上下文和 KV Cache 容量

其中，Scale-In 不是通常所说的芯片内部互连，而是英伟达给计算节点访问数据中心服务定义的新路径。BlueField-4 管理这条路径的安全与资源，Spectrum-X 则从 Scale-Out 开始承担集群级通信。

图 1：五类网络分别处理节点内 GPU 互连、节点服务访问、集群扩展、跨站点连接和上下文存储。

二、BlueField-4：把基础设施移出租户主机

2.1 DPU 成为平台的可信实体

传统服务器通常由主机操作系统直接管理网卡、存储和安全策略。这意味着租户工作负载与数据中心控制面共享同一个信任边界，基础设施服务也会占用主机 CPU。

BlueField-4 在主机前增加一个独立服务器域。上层租户域包含 CPU、GPU、LPU、模型权重、LLM 请求和用户数据；下层 BlueField DPU 运行自己的 DPU OS 与 DOCA，控制网络、存储和安全；再向下才是数据中心共享资源。基础设施策略因此不需要依赖租户操作系统执行。

图 2：BlueField 位于主机与共享资源之间，成为网络、存储和安全策略的独立执行点。

这种设计带来三个直接作用：

  1. 隔离：租户操作系统不能绕过 DPU 直接控制数据中心网络；
  2. 卸载：网络、存储、安全和遥测不再持续占用主机 CPU；
  3. 统一策略：流量进入网络之前即可完成认证、加密、访问控制和可观测性处理。

2.2 从通用 Cloud DPU 转向 AI-Native DPU

面向普通云服务器的 DPU 通常对应一块可插拔网卡和约 200 Gb/s 的网络。Vera Rubin 计算托盘却包含多条 800 Gb/s 链路，GPU Scale-Out、服务访问和管理流量合计接近 7 Tb/s。若为每块网卡复制一套 CPU、内存、管理接口和 DPU，功耗、成本与布线复杂度都会快速增加。

BlueField-4 将 Grace CPU 与 ConnectX-9 网络、存储和安全加速器组合起来：

  • 64 个 Arm Neoverse V2 核心，频率 1.7 GHz；
  • 275 GB/s LPDDR5 CPU 内存带宽；
  • 800 Gb/s Ethernet 与 200G PAM4 SerDes；
  • PCIe Gen6 x16；
  • 200 MPPS 包处理和 25 MIOPS 存储处理；
  • 支持 PSP、TLS、IPsec 和 AES-XTS 等内联加密。

图 3：Grace CPU 处理复杂控制逻辑，ConnectX-9 数据面负责高速网络、存储和内联安全。

这里的 CPU 与加速器承担不同任务：ConnectX-9 处理 RDMA、TCP/IP、交换、路由、加密和存储 I/O；Grace CPU 管理密钥、会话、连接状态、存储卷、遥测和健康检查。高频数据面由硬件加速，变化更复杂的控制面仍保留可编程 CPU。

2.3 Astra 用一个控制域接管 7 Tb/s 数据路径

英伟达通过 Astra 将一颗 BlueField-4 与计算托盘中的多颗 ConnectX-9 连接起来，使 DPU 能在不经过租户主机的情况下统一控制约 7 Tb/s 聚合流量。每条外部链路仍是 800 Gb/s，因此 7 Tb/s 是 Vera Rubin 托盘级汇总能力，不是单个 BlueField-4 端口速率。

图 4：Astra 把多颗 ConnectX-9 纳入同一 BlueField-4 控制域，使 Scale-In 与 Scale-Out 流量都经过可信数据路径。

集中式 DPU 不需要在每块网卡旁重复配置 CPU 和内存，却仍能对所有链路执行零信任策略、加密和遥测。英伟达给出的测试曲线显示，加密和虚拟化后的 Scale-Out 带宽可以随 1 至 8 块网卡接近线性增长。

2.4 用 Storage-Scale 扩展智能体上下文

智能体会话不断累积上下文，KV Cache 不能永远留在容量有限的 GPU HBM 中。英伟达因而把上下文存储划分成多级：G1 HBM 保存活跃 KV，G2 系统内存用于暂存和溢出，G3 本地存储保存可复用的温热 KV，G3.5 CMX 与 G4 通过 Scale-In 网络提供更冷或共享的上下文。

图 5：上下文根据活跃程度在 HBM、系统内存、本地存储和共享存储之间分层放置。

BlueField-4 与 DOCA MEMOS 负责端到端的数据移动和管理。英伟达为基于 Vera CPU 与 ConnectX-9 的 Storage-Scale 系统给出 3.2 Tb/s 存储访问、10 倍 IOPS 和 5 倍能效，但比较基线和完整配置需要结合实际部署进一步确认。其设计意义在于让 GPU 保留热数据，把容量扩展和状态管理转移到独立基础设施层。

三、Spectrum-X：从多轨扩展到多平面

3.1 多轨网络为什么仍然受规模限制

Spectrum-X Multi-Rail 为每块 Rubin GPU 提供 1.6 Tb/s Scale-Out 带宽，并用 4 条 Rail 分散流量。采用约 100 Tb/s、64 个 1.6 Tb/s 端口的交换机时，这种结构可连接约 8,000 块 GPU。

Rail 可以隔离不同 GPU 端口产生的通信，但如果每条高速端口仍以较粗粒度连接少量交换机，交换机端口数会限制网络规模；继续增加多级交换机又会引入更多跳数、设备、功耗和故障点。

3.2 用 200G 端口和 8 个 Plane 扩展路径多样性

Spectrum-X Multiplane 将约 100 Tb/s 交换容量组织为 512 个 200 Gb/s 端口，并构建 8 个 Plane、4 条 Rail。SuperNIC 把一块 GPU 的 1.6 Tb/s 聚合流量分散到多个独立平面，硬件全局自适应路由再根据路径状态选择可用链路。

图 6：细粒度 200G 端口把每块 GPU 分散连接到多个交换平面，扩大端口规模和可选路径数量。

在相同的单 GPU 1.6 Tb/s 带宽下，英伟达把最大规模从 Multi-Rail 的 8,000 块 GPU 提高到 Multiplane 的 512,000 块 GPU，即 64 倍。扩展来自更高端口基数和多个并行平面，而不是简单叠加更多传统 Clos 层级。

3.3 扁平多平面减少交换机数量

传统单轨多级网络需要接入、汇聚和核心交换层。Multiplane 让 SuperNIC 直接分散连接多个交换平面，在获得路径多样性的同时减少中间层级。英伟达估算，这种 Multi-Plane Multi-Rail 结构可以节省 1.7 倍 Scale-Out 交换机，从而同步降低机架空间、功耗和成本。

图 7：多平面拓扑使用多个并行直连平面替代更深的多级交换结构。

3.4 故障时保留大部分带宽

多平面的另一项价值是故障不必让整个通信域停顿。某个平面或链路失效后，其余平面仍能承载流量；Spectrum-X 的硬件故障检测、自适应路由和拥塞控制负责把流量转移到剩余路径。

在英伟达给出的故障场景中，Spectrum-X 用 2.68 ms 检测故障，检测期间仍保留约 90% RDMA 带宽，并在 100 ms 内恢复完整带宽。对比的通用以太网多平面方案检测和恢复各需 1,080 ms，检测阶段带宽降为零。英伟达据此给出 400 倍更快的检测、11 倍更快的恢复和 1.6 倍 AI Factory Goodput。

图 8：Spectrum-X 在故障检测和重新收敛期间保留可用平面，因此只损失部分带宽。

在正常负载下，英伟达还给出相对通用以太网的 1.6 倍 RDMA 带宽、2.2 倍多租户带宽和更低抖动；DeepSeek V3 多作业训练性能提高 1.9 倍，部分 NCCL 操作最高提高 14 倍。这些结果对应特定模型、消息模式和并发环境，更适合说明拥塞控制与噪声隔离的作用，而不是作为所有工作负载的固定加速比。

四、围绕多平面网络补齐光互连与跨站点扩展

当集群扩展到几十万块 GPU 时，光模块本身会成为功耗和可靠性的重要组成部分。Spectrum-X Photonics 使用微环调制器 CPO、3D 堆叠硅光引擎和可拆卸光纤连接器，把光电转换进一步靠近交换芯片。英伟达给出的目标是减少激光器数量与光互连功耗，使高基数多平面网络能够在机架空间和供电约束下继续扩展。

跨数据中心的 Spectrum-XGS 则把同一套思路延伸到 Scale-Across：102.4 Tb/s 交换机和 800 Gb/s ConnectX-9 SuperNIC 配合距离感知负载均衡与拥塞控制，减少跨站点通信对分布式作业的拖累。DSX 平台进一步承担整套 AI Factory 的仿真、验证、软件部署和运行管理。

五、BlueField-4 与 Spectrum-X 如何形成一条数据路径

两项技术组合后，一次 Scale-Out 通信大致经过以下边界：

  1. GPU 或 CPU 在租户域中产生 RDMA、存储或服务请求；
  2. BlueField-4 在独立可信域中执行身份、策略、加密和遥测；
  3. ConnectX-9 将流量送入 Spectrum-X 的 Rail 与 Plane；
  4. Spectrum-X 根据全局路径和拥塞状态选择可用平面；
  5. 目标节点的 BlueField-4 再次执行基础设施策略后，把数据交给租户工作负载。

这条路径将“谁可以发送”和“怎样送达”分开：BlueField-4 负责信任边界与节点级服务，Spectrum-X 负责集群级带宽、路径选择和故障恢复。主机不再同时承担计算、基础设施控制和网络异常处理。

六、设计亮点与边界

BlueField-4 的亮点不是单纯提高 DPU 核心数，而是用 Grace CPU、ConnectX-9 和 Astra 把一个托盘的全部数据路径纳入同一可信控制域；Spectrum-X 的亮点也不只是更快的交换芯片，而是通过多轨、多平面和硬件自适应路由，把交换容量转换成规模、路径多样性和故障期间的有效带宽。

同时需要注意三个边界：

  • 7 Tb/s 是 Vera Rubin 托盘的聚合数据路径，不是 BlueField-4 的单端口带宽；
  • 512,000 GPU 是在 1.6 Tb/s/GPU、100T 交换机、512×200G 端口、8 Plane 和 4 Rail 配置下的拓扑规模；
  • 1.6 倍 Goodput、1.7 倍交换机节省及存储能效等数字均来自英伟达给定配置，不能脱离流量模式、故障模型和比较基线直接泛化。

七、总结

英伟达为 AI Factory 增加的不是一块更快的网卡，而是两层新的系统结构：BlueField-4 把基础设施变成独立、可信、可编程的节点级操作域，Spectrum-X Multiplane 把这个操作域延伸成可扩展、可绕障的集群网络。

前者通过卸载与隔离保护 GPU、模型权重和用户数据，后者通过细粒度端口、并行平面和硬件路由提高规模与可用带宽。两者共同体现了 AI 基础设施的一个变化：计算性能不再只取决于 GPU，而取决于整条数据路径能否以同样的速度完成访问控制、数据移动和故障恢复。
