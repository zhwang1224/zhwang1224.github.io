NVLink的技术演进

发表于 2026-09-19 更新于 2026-09-20 分类于 人工智能系统 ， 高性能互连 阅读时长 ≈ 17 分钟
从 Pascal 的点对点互连，到 NVSwitch 交换网络与 NVL72 机架级系统，梳理 NVLink 六代技术在链路带宽、拓扑、集合通信和可靠性上的变化。

上一篇讨论了为什么多 GPU 系统需要更快的互连。这篇文章继续追问：当 GPU 的数量和通信需求不断增加，NVLink 如何从几张卡之间的高速连接，发展为覆盖整个机架的交换网络？

这段演进包含三种变化：每张 GPU 可以收发更多数据，更多 GPU 可以进入同一个高速互连域，交换网络开始承担部分集合通信和系统管理工作。只有把链路、交换芯片和整机配置分开，才能准确理解各代技术的进步。

本文以 NVIDIA 官方架构介绍、产品资料和 CUDA 文档为依据，资料核对截至 2026 年 9 月 20 日。

1. 先区分链路、交换芯片和系统

NVLink 是互连技术。GPU 可以通过多条 NVLink 连接其他 GPU，也可以连接交换芯片。NVSwitch 是转发 NVLink 流量的交换芯片；由这些芯片、连接线缆及管理软件组成的交换系统，可以连接更多 GPU。NVLink 域（domain） 则描述一个具体系统中通过 NVLink 网络互连的 GPU 范围。

因此，某代 NVLink 并不只对应一种 GPU 数量或一种拓扑。例如，同代 GPU 既可以采用少量设备之间的直接连接，也可以接入多颗 NVSwitch 构成的网络。

2. NVLink 1：从 PCIe 通信走向专用 GPU 互连

2016 年的 Tesla P100 SXM2 将第一代 NVLink 带入实际产品。每张 GPU 有 4 条链路，每条单向 20 GB/s、双向 40 GB/s，合计双向 160 GB/s。每块P100 GPU集成了4条NVLink 1.0链路。每条NVLink 1.0链路由8对差分线（8个通道）组成。每对差分线（每个通道）的双向带宽是5GB/s。所以，每条NVLink 1.0链路的双向带宽是40GB/s。因此，每块P100 GPU的总双向带宽可达160GB/s，是PCIe3 x16（总带宽大约32GB/s）的五倍。

NVLink还支持内存一致性和直接内存访问（DMA），进一步提高了数据传输效率和计算性能。

Tesla P100 加速器以两种形式提供：一种是适用于 PCIe 服务器的传统 GPU 加速板，另一种是适用于 NVLink 优化服务器的 SXM2 模块。Inside Pascal

第一代的重要变化，是在原有主机 I/O 路径之外，为 GPU 间通信提供专用连接。在 x86 DGX-1 中，CPU 与 GPU 仍通过 PCIe 连接，8 张 P100 则组成 Hybrid Cube Mesh 混合立方体网格。DGX-1 系统架构

图 1 第一代 NVLink 的 DGX-1 拓扑。绿色连接组成两个四卡全连接子图，并通过四条 NVLink 相连；每张 P100 直接连接四个邻居。紫色为 PCIe，顶部灰色为 CPU 间 QPI，图中的 PCIe Switch 不是 NVSwitch。来源：NVIDIA DGX-1 系统架构，原文图 4。

这个拓扑可以看成一个立方体：8 张 GPU 位于顶点，12 条棱对应连接，再在两个相对的面上加入对角连接。每张 GPU 直接连接 4 个邻居，使用完自己的 4 条 NVLink。

这也揭示了直接连接的限制。8 张 GPU 若要两两直接相连，每张 GPU 至少需要连接 7 个邻居；4 条链路无法满足这一要求。软件需要根据实际连接组织通信。

第一代解决了直接相连 GPU 之间的带宽问题，但不同 GPU 对之间的连接条件仍然不同。新增算力能否被充分利用，开始更明显地依赖拓扑与通信算法的配合。

3. NVLink 2 与第一代 NVSwitch：从固定邻居到交换网络

Volta V100 将 NVLink 链路数提高到 6 条，每条双向 50 GB/s，整卡合计双向 300 GB/s。相对 P100 SXM2 的 160 GB/s，增加来自链路数量和单链路带宽两个方面。Volta Tuning Guide

不过，增加链路数量并不会自动消除拓扑约束。只要链路直接接到某个邻居，这部分物理带宽就被分配给了这个邻居。其他通信对能否利用它，需要看路径和软件组织方式。

2018 年，DGX-2 使用第一代 NVSwitch 连接 16 张 V100。单颗 NVSwitch 提供 18 个 NVLink 端口，内部使用全连接交叉开关。每块 GPU 基板配置 8 张 GPU 和 6 颗交换芯片，每张 GPU 分别用一条链路连接每颗交换芯片；两块基板之间再通过 NVLink 连接。NVSwitch 技术介绍

图 2 第二代 NVLink 与第一代 NVSwitch 的 16 GPU 连接方案。图示为 HGX-2 双基板逻辑拓扑：每块基板有 8 张 V100 和 6 颗 NVSwitch，两板之间共有 48 条 NVLink。这是与本节 DGX-2 相对应的基板级架构，300 GB/s 指每 GPU 双向聚合带宽。来源：NVIDIA HGX-2 架构介绍，原文图 1。

架构变化在于：GPU 不再需要把有限端口逐一分给所有通信对象，而是将链路接入交换网络，由网络把数据送到目标。

用一个简化例子理解：假设一张 GPU 的单向总带宽为 120 GB/s，直接连接三个邻居时，各分配 40 GB/s。如果任务只和其中一个邻居通信，另外两组链路通常不能直接变成这个通信对的额外物理带宽。接入容量充足的交换网络后，同样的 120 GB/s 接口预算可以用于不同目标，而不必按邻居永久切开。

这不意味着同时向三个目标各发送 120 GB/s。交换网络改善的是路径选择和带宽使用的灵活性，端点总预算仍然是 120 GB/s。这个区别是理解 NVSwitch 的基础。

4. NVLink 3：提高带宽，形成灵活的多 GPU 基板

2020 年的 A100 提供 12 条第三代 NVLink，整卡双向带宽达到 600 GB/s。其每条链路使用的物理通道数量和信号速率发生变化，但每条逻辑链路仍提供单向 25 GB/s、双向 50 GB/s。因此，单条物理 lane 的速率与整条 NVLink 的带宽不能混为一谈。Ampere 架构说明

HGX A100 的 8 GPU 基板配置 6 颗 NVSwitch，将每张 GPU 的 12 条链路接入交换网络。官方资料还描述了两块基板背靠背连接、组成 16 GPU 系统的方案。因此，“常见配置是 8 GPU”与“这一代只能连接 8 GPU”是两回事。HGX A100 平台介绍

图 3 第三代 NVLink 的 HGX A100 八卡基板。每张 A100 通过 12 条 NVLink 接入 6 颗 NVSwitch；图中 600 GB/s 是每 GPU 的双向聚合带宽，上方 PCIe Gen4 接口是另一条 I/O 路径。来源：NVIDIA HGX A100 平台介绍，原文图 1。

同一平台也提供 4 GPU 直接连接的基板，每对 GPU 的双向带宽为 200 GB/s。它面向不同的 CPU/GPU 配比、功率和资源分配需求。这说明引入 NVSwitch 后，直接连接并没有失去意义：系统规模较小、通信关系明确时，点对点拓扑仍是一种选择。

这一阶段更适合用“系统配置逐渐丰富”来理解。NVLink 提供带宽，基板决定如何分配这些链路，交换网络决定不同通信模式可以怎样使用它们。

5. NVLink 4：跨节点互连与集合通信卸载

2022 年的 Hopper H100 将链路数增加到 18 条，双向聚合带宽达到 900 GB/s，是 A100 的 1.5 倍。每条逻辑链路仍为双向 50 GB/s。HGX H100/H200 的 8 GPU 系统使用 4 颗第三代 NVSwitch 组织 GPU 间通信。Hopper 架构说明、Hopper 多 GPU 互连

图 4 第四代 NVLink 的 Hopper 基板实例。原图型号为 HGX H200，展示 8 GPU 基板上 4 颗第三代 NVSwitch 的位置；H200 与本节 H100 同属第四代 NVLink 平台。此图展示节点内硬件，不代表下文的 256 GPU 跨节点网络。来源：NVIDIA 多 GPU 推理互连介绍，原文图 3。

更重要的变化发生在网络和交换功能上。

从单机接线扩展为跨节点网络

Hopper 的公开架构包含 NVLink Network 和节点外的 NVLink Switch System。它引入网络地址空间及地址隔离机制，描述了最多 32 个节点、256 张 GPU 的连接方案，拓扑为 2:1 收敛的 Fat-tree。这里的收敛意味着对外链路容量小于节点内部总接口容量，跨节点通信不能直接按节点内峰值估算。

这项能力属于特定交换系统方案。原始架构文章也注明了当时的可用性限制，因此不能仅凭服务器装有 H100，就认定它支持或已经部署了 256 GPU 的 NVLink 域。Hopper：NVLink Switch System

交换芯片开始参与集合通信

第三代 NVSwitch 加入多播和 SHARP 网内归约能力。普通交换只负责转发数据；网内归约则能在支持的集合通信路径中合并部分数据，减少 GPU 侧执行归约的负担。Hopper：第三代 NVSwitch

归约和多播是不同操作：ReduceScatter 涉及归约，AllGather 则是收集与分发，不能把所有集合通信加速都称为“做规约”。实际应用还需要通信库选择支持这些硬件能力的算法。

因此，这一代的进步不能只用 600 → 900 GB/s 表达。互连开始具备跨节点寻址、隔离和通信处理能力，逐步形成一套网络系统。

6. NVLink 5：把高速互连域扩展到机架

Blackwell 第五代 NVLink 保持每 GPU 18 条链路，将每条双向带宽提高到 100 GB/s，整卡达到 1.8 TB/s。GB200 NVL72 是这一代具有代表性的系统：72 张 Blackwell GPU 通过 NVLink Switch System 形成一个高速互连域。GB200 NVL72 架构介绍

图 5 第五代 NVLink 的 GB200 NVL72 交换系统。图中展示 9 个交换托盘及其 cable cartridge 连接组件；计算托盘未显示。它对应单个 72 GPU 域，不能将图中的硬件直接理解为后文提及的 576 GPU 扩展配置。来源：NVIDIA GB200 NVL72 架构介绍，原文图 2。

对模型并行而言，72 GPU 域的意义在于：原本需要跨越多个小型 NVLink 域的通信，有机会在一个更大的高速域内完成。是否因此加速，仍取决于模型划分、通信量、负载均衡和计算通信重叠。

2026 年的 Vera Rubin 平台继续发展第六代 NVLink。但截至本文核对日期，两份 NVIDIA 官方资料给出的带宽并不一致：

NVLink 产品页 3.0 TB/s 216 TB/s 页面标注为初步规格，最多 36 条链路
2026-07-20 技术博客 3.6 TB/s 约 260 TB/s 文章对 Vera Rubin NVL72 的描述

两组数字各自满足机架聚合关系：，。但算术自洽不能判断哪组对应最终配置，也不能把产品页的“36 条链路”和另一篇文章的“3.6 TB/s”拼接起来，直接认定单链路规格为 100 GB/s。本文保留来源差异，不据此给出唯一的单链路带宽结论。

在系统能力上，第六代资料强调了控制面韧性、部分填充机架运行、交换托盘热插拔和动态重路由。随着互连域扩大，一条链路或一个交换托盘的故障可能影响更多 GPU，监测、隔离和维护能力也就成为系统设计的一部分。

8. 将六代变化放在一起看

下面只汇总代表性配置。年份对应产品或平台公开介绍的阶段；带宽指支持相应连接的代表性 GPU 配置，并非同名 GPU 所有板卡型号都具有相同能力。

图 7 技术演进示意。图中列出代表性系统变化，不表示每代只支持一种拓扑；更大规模的网络也不会自动取代小规模配置。

从这条主线可以看出，NVLink 的演进逐渐超出了单条连接的提速：NVSwitch 改变了带宽的组织方式，NVLink Network 扩大了互连范围，NVL72 将计算、交换、布线与维护一起纳入机架设计。

还需要保留两个边界。首先，GPU 间的 NVLink 与 CPU–GPU 的 NVLink-C2C 是不同连接，后者的一致性能力不能直接推广为整个 GPU 域自动拥有统一、等速的显存。其次，NVLink 扩大 Scale-up 域，并不意味着 Scale-out 网络失去作用；InfiniBand 或以太网仍用于连接更大范围的计算资源。具体并行任务放在哪一层，应由通信需求和实际拓扑决定。
