TCP/IP 协议

发表于 2026-09-13 更新于 2026-09-21 分类于 计算机网络 阅读时长 ≈ 4 分钟
TCP/IP 协议栈的分层职责，以及数据的封装与解封装过程

计算机之间通信时，双方需要遵循共同的规则，才能有序地发送和接收数据。TCP/IP（Transmission Control Protocol/Internet Protocol）是互联网采用的基础协议族，它规定了数据如何在应用、主机与互连网络之间传递。

TCP/IP 协议栈

TCP/IP 是以 IP 为核心的一组互联网协议。RFC 1122 将互联网协议族划分为应用层、传输层、网络层和链路层。工程教材常把链路层下面的物理传输单独列出，形成五层模型。

层次 解决的问题 典型协议或技术 常用数据单位
应用层 定义应用消息的语义与交互规则 HTTP、TLS、DNS、SSH 消息、记录或字节
传输层 为应用进程提供端到端通信 TCP、UDP TCP 段、UDP 数据报
互联网层（网络层） 跨越多个网络进行寻址和逐跳转发 IPv4、IPv6、ICMP、ICMPv6 IP 数据报（分组）
链路层 在一条本地链路上交付数据 Ethernet、Wi-Fi、PPP、ARP 帧
物理层 在介质上传输编码后的比特 双绞线、光纤、无线电 比特或信号

从应用数据到链路帧

应用通常通过 socket API 使用传输层服务：向 TCP 写入连续字节，或者把一条消息交给 UDP 作为一个数据报发送。数据随后沿协议栈向下，依次经过传输层、网络层、链路层和物理层。

发送 TCP 数据时，TCP 依据 MSS 等限制把字节流组织成段，并受发送窗口和拥塞窗口约束安排发送；UDP 则保留每次发送的数据报边界。TCP 或 UDP 添加包含源端口、目的端口和校验和等字段的传输层首部。IP 再添加包含源、目的 IP 地址等字段的首部，形成 IP 数据报。链路层为当前一跳添加链路封装；以 Ethernet 为例，帧包含链路层首部和帧校验序列（FCS）。物理层最终把帧对应的比特编码为电、光或无线信号。

接收端沿相反方向处理数据：从信号中恢复比特并识别帧，处理链路层封装，再由 IP 根据首部中的上层协议字段完成分用，最后由 TCP 或 UDP 根据端口把数据交给相应的 socket。每层处理自己负责的控制信息，并把载荷交给上一层。

两台主机都可以同时发送和接收。尤其是 TCP 连接，其两个方向彼此独立，任一端发送时数据沿本机协议栈向下，另一端接收时数据沿协议栈向上。

不同层次的主要功能

  • 应用层规定消息格式、字段语义和交互顺序。例如，HTTP 定义请求与响应，DNS 定义查询与资源记录。加密、身份认证和消息边界也可能由这一层的协议负责。
  • 传输层通过端口把数据交付给目标主机上的具体应用。TCP 提供面向连接、可靠、有序的字节流，并实现重传、流量控制和拥塞控制；UDP 提供无连接的数据报服务，不保证到达、顺序或唯一性，也不替应用执行重传和拥塞控制。
  • 网络层使用 IP 地址标识接口，并让 IP 数据报跨越多个网络逐跳到达目标主机。IP 提供尽力而为的无连接服务，路由器主要在这一层查询转发表并选择下一跳。
  • 链路层负责把 IP 数据报交付给同一链路上的下一跳。链路层地址、帧格式、MTU 和差错检测通常只对当前一跳有效；经过路由器后，IP 数据报会为下一条链路重新封装。
  • 物理层负责把比特映射为介质上的信号，并规定编码、调制、时钟和电气或光学特性。
