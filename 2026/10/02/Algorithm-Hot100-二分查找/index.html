Algorithm-Hot100-二分查找

Hot100 算法题思路汇总-二分查找

  1. 搜索插入位置

给定一个升序且元素互不相同的数组 nums 和一个目标值 target，返回 target 在数组中的下标。如果 target 不存在，返回它按升序插入后应处的位置。

核心思路：在半开区间 [left, right) 上查找第一个大于等于 target 的位置。初始区间是 [0, n)。取中点后只比较一次：

  • nums[mid] < target：mid 以及它左侧都小于目标，插入点只能在 mid 右边，令 left = mid + 1。
  • 否则 nums[mid] >= target：mid 仍可能是答案，令 right = mid，把 mid 留在区间内。

循环条件是 left < right。结束时 left == right，这个下标就是第一个大于等于 target 的位置，也就是插入位置。target 大于全部元素时，left 会停在 n，表示插到数组末尾。

时间复杂度：O(log n)；空间复杂度：O(1)。

  1. 搜索二维矩阵

给定一个 m 行 n 列的矩阵和一个目标值 target。矩阵每行从左到右递增，并且每一行的第一个数都大于上一行的最后一个数。判断 target 是否在矩阵中。

核心思路：把矩阵按行展开，得到一个长度为 m * n 的升序序列。展开后的下标 mid 对应矩阵中的 matrix[mid / n][mid % n]。之后仍用上一题的半开区间，查找第一个大于等于 target 的位置。

循环结束时还要确认两件事：下标没有落到 m * n，并且该位置的值确实等于 target。只找到“第一个大于等于 target 的位置”还不能说明目标存在。

时间复杂度：O(log(mn))；空间复杂度：O(1)。

  1. 在排序数组中查找元素的第一个和最后一个位置

给定一个非降序数组 nums 和一个目标值 target，返回 target 在数组中第一次和最后一次出现的下标。不存在时返回 [-1, -1]。

核心思路：把“找等于 target 的区间”拆成两次“找第一个大于等于某个值的位置”。记 lower(x) 为第一个大于等于 x 的下标，实现和搜索插入位置相同。

lower(target) 是 target 的起点。因为数组元素都是整数，lower(target + 1) - 1 是最后一个小于 target + 1 的位置，也就是 target 的终点。起点处的值不等于 target，或者起点已经落到数组末尾时，说明 target 不存在。

元素范围在 [-10^9, 10^9] 内，target + 1 不会溢出 int。

时间复杂度：O(log n)；空间复杂度：O(1)。

  1. 搜索旋转排序数组

一个升序且元素互不相同的数组，在某个未知下标处被旋转了一次。例如 [0,1,2,4,5,6,7] 可能变成 [4,5,6,7,0,1,2]。给定旋转后的数组和目标值 target，返回它的下标，不存在时返回 -1。

核心思路：旋转一次后，数组被分成两段各自有序的区间，后一段的元素都小于前一段。在当前半开区间 [left, right) 中取 mid，两侧至少有一侧仍然连续有序：

  • nums[left] <= nums[mid] 时，[left, mid] 有序。
  • 否则旋转点落在左半边，[mid, right) 有序。

有序的一侧可以直接判断 target 是否落在其中。左半边有序时，范围是 nums[left] <= target < nums[mid]，满足则令 right = mid。右半边有序时，范围是 nums[mid] < target <= nums[right - 1]，满足则令 left = mid + 1。两种情况都不满足时，答案在另一侧。这里的 nums[right - 1] 是当前窗口的最后一个元素，不是整个数组的最后一个元素。

元素互不相同，nums[left] <= nums[mid] 中的等号只在 left == mid、区间只剩一个元素时出现。若这个元素还不是目标，left 会变成 mid + 1，区间继续收缩。

时间复杂度：O(log n)；空间复杂度：O(1)。

  1. 寻找旋转排序数组中的最小值

一个元素互不相同的升序数组被旋转了若干次，返回其中的最小元素。旋转整数组次数时，数组会回到原来的顺序。

核心思路：最小值是两段有序区间的分界。它左侧的元素都大于原数组的最后一个元素，它自己和右侧的元素都小于等于最后一个元素。例如 [4,5,6,7,0,1,2] 的末尾是 2，大于 2 的 4,5,6,7 全部位于最小值左边。

因此每次把 nums[mid] 和整个数组的最后一个元素 nums.back() 比较，比较对象不随窗口变化：

  • nums[mid] > nums.back()：mid 还在左段，最小值在它右侧，令 left = mid + 1。
  • 否则 mid 已经落在包含最小值的右段，令 right = mid，把 mid 保留在区间里。

数组没有发生实际旋转时，任何元素都不大于末尾元素，区间一直向左收缩，最后停在下标 0。半开区间结束时 left 就是最小值的下标，不会走到 n。

时间复杂度：O(log n)；空间复杂度：O(1)。

  1. 寻找两个正序数组的中位数

给定两个升序数组 nums1 和 nums2，返回它们合并后的中位数。总元素个数至少为 1，算法需要达到 O(log(m + n))。

核心思路：在较短的数组上二分切割位置。先把两个数组划分成左右两半，让左半边的元素个数是 half = (m + n + 1) / 2。总长度为奇数时，左半边恰好多一个元素，中位数就是左半边的最大值。

设从 nums1 取 i 个元素进入左半边，那么从 nums2 取 j = half - i 个。记四条边界为：

  • aLeft = nums1[i - 1]，aRight = nums1[i]
  • bLeft = nums2[j - 1]，bRight = nums2[j]

切割合法，当且仅当左半边的每个值都不大于右半边，也就是 aLeft <= bRight 并且 bLeft <= aRight。某一侧没有元素时，用 INT_MIN 或 INT_MAX 充当哨兵。

aLeft > bRight 说明 nums1 放入左半边的元素过多，切割点向左移动；否则是 nums2 的左端过大，切割点向右移动。i 可以取 0 到 m，表示一个元素都不取或全部取走，所以这里使用闭区间 [0, m]，收缩时写成 right = i - 1 或 left = i + 1。

找到合法切割后，奇数长度返回 max(aLeft, bLeft)；偶数长度返回左半边最大值与右半边最小值的平均数。平均数要除以 2.0，否则 1 和 2 的平均数会变成整数 1。

先保证在较短的数组上二分，时间复杂度是 O(log min(m, n))，空间复杂度是 O(1)。元素范围在 [-10^6, 10^6] 内，两个真实边界相加不会超出 int；左半边至少有一个元素，两个哨兵也不会同时被当成中位数。
