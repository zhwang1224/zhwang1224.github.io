张量并行

张量并行（Tensor Parallelism，TP）是一种层内模型并行方法。它不是把不同层放到不同 GPU，而是把同一层中的权重矩阵、注意力头以及相关计算沿某个张量维度切分，让一组 GPU 共同完成这一层的前向和反向传播。

一句话概括：

数据并行切数据，流水线并行切层，张量并行切一层内部的矩阵与计算。

Megatron-LM 推广的张量并行方案之所以重要，在于它没有机械地在每个线性层后都恢复完整张量，而是精心组合列并行与行并行，使中间激活保持分片状态，将通信集中到 Transformer 子模块的少数边界上。

1. 为什么需要张量并行

流水线并行可以把不同 Transformer Block 放到不同设备，但它有一个前提：至少一个完整 Block 能够在某个流水线 Stage 内高效执行。当隐藏维度、MLP 中间维度、词表或单层参数量继续增大时，单个 Transformer Block 本身也可能无法放入一张 GPU，或者单卡计算时间已经成为瓶颈。

这时仅仅继续增加流水线 Stage 并不能拆开单层内部的大矩阵。张量并行解决的就是这个问题：把一个大矩阵乘法分解为多个较小矩阵乘法，由多个 Rank 同时完成。

设张量并行度为 ，一个 TP Group 包含 个 Rank。理想情况下：

  • 可切分线性层的参数、梯度和优化器状态约缩小到原来的 ；
  • 大型矩阵乘法的主要 FLOPs 约分摊到 个设备；
  • 代价是在 Transformer Block 内引入频繁的 AllReduce、AllGather 或 ReduceScatter；
  • 同一 TP Group 中的 Rank 必须以接近锁步的方式执行，最慢 Rank 和通信链路决定整体速度。

因此，TP 不是“免费获得 倍加速”。它是一种用通信换取单层容量和并行计算能力的技术。

并行方式 切分维度 每个设备保存 主要通信位置
数据并行（DP） Batch 完整模型副本 反向传播中的梯度同步
流水线并行（PP） 模型深度 一段连续层 Stage 边界激活与激活梯度
张量并行（TP） 层内隐藏维度、注意力头等 每层权重的一部分 几乎每个 Transformer Block 内部

3.3 前向和反向各通信什么

在不使用 Sequence Parallel 的经典实现中，一组 Column-Parallel + Row-Parallel MLP 的主要通信是：

  • 前向：行并行输出执行一次 AllReduce；
  • 反向：列并行输入梯度执行一次 AllReduce；
  • 中间激活：保持最后一维分片，不需要 AllGather；
  • 权重梯度：对应权重本来就由不同 Rank 持有，因此在 TP 维度上通常本地计算，不需要把完整权重梯度聚合到每个 Rank。

这里最后一点只针对 TP Group。若外层还使用数据并行，同一个权重分片在不同 DP Replica 之间仍然需要执行梯度同步或分片归约。

4.4 MHA、GQA 与 MQA 的切分约束

标准 MHA 中，通常要求 Attention Head 数可以被 TP Degree 整除。GQA 和 MQA 则需要更谨慎：

  • GQA 的 Query Head 数量多于 KV Head 数量，Query 与 KV 的分片映射必须保持分组关系；
  • 如果 TP Degree 不大于 KV Head 数且能够整除，通常可以把 KV Head 一并切分；
  • 如果 TP Degree 大于 KV Head 数，某些实现会复制 KV Head，某些实现使用更复杂的映射；
  • MQA 只有一组 KV Head，不能简单假设它能像 Query Head 一样均匀切到所有 Rank。

因此，“Attention 就是按 Head 数平均分”只对结构和整除条件合适的 MHA 成立。实际配置必须检查框架对 GQA/MQA 的实现约束。

5.2 经典 TP 的集合通信次数

对一个 Decoder-only Transformer Block：

  • Attention：输出投影后一次前向 AllReduce，QKV 投影输入梯度一次反向 AllReduce；
  • MLP：Down Projection 后一次前向 AllReduce，Gate/Up 或第一层投影输入梯度一次反向 AllReduce。

因此，经典 Megatron TP 通常可以理解为每个 Transformer Block 前向两次 AllReduce、反向两次 AllReduce。这四次通信位于依赖链上，频率远高于数据并行中通常每个训练步对梯度 Bucket 执行的通信。

该结论针对基础 Megatron 风格 TP。使用 Sequence Parallel、通信融合、异步重叠、并行残差结构或其他张量布局时，AllReduce 可能被等价地改写为 AllGather 与 ReduceScatter，具体次数也可能变化。

6. Sequence Parallel：为什么 TP 还需要 SP

6.1 基础 TP 没有切分所有激活

基础 TP 主要切分 Attention 和 MLP 内的大型线性层，但 Transformer Block 外部的输入输出通常仍然在 TP Group 中复制：

RMSNorm / LayerNorm、Dropout 和残差连接的参数很少，直接复制计算实现最简单。然而它们相关的激活会随 、 和 增长。模型很大或序列很长时，复制激活会成为显存瓶颈。

6.2 SP 的 AllGather 与 ReduceScatter

Sequence Parallel（SP）在 TP Group 内沿 Sequence 维切分这些非 TP 区域的激活：

LayerNorm / RMSNorm 是对每个 Token 的隐藏维度独立归一化，Dropout 和残差加法也可以逐 Token 执行，所以每个 Rank 可以只处理自己的 Token 子序列。

进入需要复制输入的 Column-Parallel Attention 或 MLP 前，通过 AllGather 恢复完整 Sequence；Row-Parallel 输出不再执行 AllReduce 并让每个 Rank都得到完整结果，而是执行 ReduceScatter，在求和的同时把结果重新切回 Sequence 分片。反向传播使用对应的逆向通信。

从带宽量级看，AllReduce 可以分解为 ReduceScatter + AllGather，因此 SP 的主要价值不是凭空消灭全部通信，而是让 Norm、Dropout、残差等区域的激活长期保持分片，从而降低激活显存，并为通信—计算重叠提供更细的边界。

6.3 Sequence Parallel 与 Context Parallel

两者都可能沿 Sequence 维切分，但覆盖范围不同：

对比项 Sequence Parallel Context Parallel
主要目标 切分 Norm、Dropout、Residual 等非 TP 激活 切分整个网络的长序列激活
Attention 是否持有完整序列 通常在进入 Attention 前 AllGather 各 Rank 只持有部分 Query，需要交换全局 KV 信息
典型通信 TP 边界的 AllGather / ReduceScatter Attention 内 KV 的 P2P、AllGather 或 All-to-All 等
适用问题 TP 下的激活显存 超长上下文训练

因此，SP 不能简单等同于“把 Attention 的上下文切开”。后者属于 Context Parallel、Sequence Context Parallel 或其他长序列并行方案。

8. 张量并行节省了什么

对能够均匀切分的线性层，TP 通常带来：

  • 参数：每个 Rank 约持有 ；
  • 参数梯度：每个 Rank 约持有对应权重分片的 ；
  • 优化器状态：若优化器按本地参数创建，相关状态也约为 ；
  • 大型 GEMM 计算：主要乘加量约分摊到 ；
  • Attention Head 与 MLP 中间激活：沿隐藏维度分片。

但不能笼统地说“TP 后所有显存都除以 ”：

  • 基础 TP 的 Block 输入输出、残差、Norm 和部分临时激活仍可能复制；
  • CUDA Context、通信缓冲区、Allocator 碎片等固定开销不会等比例下降；
  • 某些小参数、Bias、Norm 权重或共享权重可能复制；
  • 激活重计算、FlashAttention、混合精度和序列长度会改变显存构成；
  • 如果外层还使用 DP，DP 通信和梯度缓冲仍有独立开销。

Sequence Parallel 正是为了进一步切分基础 TP 未覆盖的激活区域。

10. TP Degree 与硬件拓扑

增大 TP Degree 会降低单卡参数和计算，却不一定提高吞吐。常见限制包括：

  1. 整除约束：隐藏维度、MLP 中间维度、Attention Head 数通常需要适配 TP Degree；
  2. GEMM 变窄：每个 Rank 的矩阵维度过小后，Tensor Core 利用率下降；
  3. Collective 延迟：每个 Block 都有通信，跨慢链路时延迟被层数反复放大；
  4. 负载同步：一个 Rank 抖动会让整个 TP Group 等待；
  5. 拓扑不对称：跨 PCIe Host Bridge 或跨节点的 TP 可能远慢于节点内 NVLink；
  6. 通信重叠受依赖限制：不是所有 AllReduce 都有足够独立计算可以隐藏。

通常应选择满足显存约束的最小 TP Degree，再用 PP、DP/FSDP 或 CP 扩展剩余设备。NVIDIA Megatron Core 当前也建议 TP 主要用于大隐藏维度和单层容量问题，并通常与 Sequence Parallel 配合。

需要通过性能分析工具观察：

  • GEMM 的实际 FLOPs 和 Tensor Core Occupancy；
  • NCCL Collective 的持续时间与链路带宽；
  • 通信是否跨越 NUMA、PCIe Switch 或节点边界；
  • 各 Rank 是否存在明显 Straggler；
  • AllGather / ReduceScatter 是否与权重梯度或激活梯度计算重叠。

小结

张量并行的核心不是“多卡分别算一部分，最后拼起来”这么简单，而是为 Transformer 中每个大矩阵选择合适的分片轴，并让相邻算子的布局彼此衔接：

  • Column Parallel 切输出通道，产生可独立处理的分片激活；
  • Row Parallel 切输入通道，产生必须求和的部分输出；
  • MLP 使用 Column → 激活函数 → Row，避免收集中间大激活；
  • Attention 使用 QKV Column → 本地 Head Attention → Output Row；
  • 基础 TP 每个 Block 存在多次关键路径集合通信；
  • Sequence Parallel 进一步切分 Norm、Dropout 和 Residual 区域的激活；
  • TP 通常放在高速节点内，与 PP、DP/FSDP、CP 共同组成混合并行系统。

判断一个 TP 方案是否优秀，不能只看参数是否均分，而要同时检查计算形状、激活布局、通信位置、网络拓扑和端到端吞吐。
