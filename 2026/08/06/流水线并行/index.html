流水线并行

流水线并行（Pipeline Parallelism，PP）是一种模型并行策略：它把一个深度神经网络沿层的方向切分为多个连续 Stage，将不同 Stage 放到不同加速器上，再把一个训练批次切成多个 Micro-batch，使不同设备能够同时处理不同 Micro-batch 的不同 Stage。

它同时解决两个问题：

  1. 容量问题：单个设备只保存和计算模型的一部分，从而训练无法完整放入单卡的大模型；
  2. 利用率问题：通过 Micro-batch 流水化，避免朴素层间模型并行中“只有一张卡工作，其余卡等待”的严重空闲。

GPipe 是经典的同步流水线方案。它把一个 Mini-batch 切成多个 Micro-batch，先完成所有 Micro-batch 的前向流水，再完成反向流水，最后统一更新参数。这种调度常被称为 Fill-Drain 或 All-Forward-All-Backward。

需要先强调：流水线并行不是“把一个算子拆到多张卡上”。它切分的是模型的层或模块；如果某个 Transformer 层本身仍然无法放入或无法在单卡高效计算，还需要结合张量并行、序列并行等其他策略。

1. 为什么需要流水线并行

1.1 什么是模型并行

模型并行（Model Parallelism）是指：把同一个模型的参数、层或层内计算拆分到多个设备上，由这些设备协作完成同一批数据的前向传播和反向传播。它解决的核心问题是模型容量，而不是把不同样本复制给不同设备计算。

第 个设备只长期保存并计算参数子集 。这些参数子集共同组成一个完整模型，任何一张设备都不必独自容纳全部参数。

模型并行是一个上位概念，常见实现包括：

  • 流水线并行（Pipeline Parallelism）：沿网络深度切分，将不同层或 Transformer Block 放到不同设备；
  • 张量并行（Tensor Parallelism）：在单层内部切分矩阵、注意力头或张量维度；
  • 专家并行（Expert Parallelism）：在混合专家模型中，将不同 Expert 分配到不同设备。

本文讨论的是流水线并行。为了便于说明，以下以 Decoder-only 大语言模型为例：Transformer Block 是由因果自注意力、前馈网络、归一化和残差连接组成的重复计算单元；LM Head（Language Model Head）则把最后的隐藏状态投影为词表中每个 Token 的 Logit。

流水线并行借鉴了工业流水线：不等第一个样本完成全部 Stage，就让下一个 Micro-batch 进入 Stage 0。稳定运行后，每个 Stage 都在处理不同的 Micro-batch。

并行方式 主要切分对象 每个设备保存什么 典型通信
数据并行（DP） 输入数据 完整模型副本 梯度 AllReduce
张量并行（TP） 层内张量与算子 单层的一部分 高频 AllReduce、AllGather 等
流水线并行（PP） 连续层或模块 若干完整层 相邻 Stage 的激活值与激活梯度

这三者并不互斥。大模型训练通常同时使用 DP、TP 和 PP，分别解决吞吐量、单层计算规模和模型总深度带来的容量问题。

GPipe 的核心是同步 Fill-Drain 调度。以 个 Stage、 个 Micro-batch 为例：

图中的 表示第 个 Micro-batch 的前向计算， 表示其反向计算。每个方格代表某个 Stage 在一个逻辑时间片中的主要工作；空白区域就是 Pipeline Bubble。

4.1 Forward Phase

前向阶段按照以下过程填充流水线：

  1. Stage 0 计算 ，把边界激活发送给 Stage 1；
  2. 下一时刻，Stage 0 计算 ，Stage 1 同时计算 ；
  3. 当第一个 Micro-batch 到达最后一个 Stage 后，流水线进入相对稳定状态；
  4. Stage 0 处理完最后一个 Micro-batch 后，前端开始排空；
  5. 最后一个 Micro-batch 离开 Stage 时，前向阶段结束。

4.2 Backward Phase

GPipe 不会在某个 Micro-batch 刚完成前向后立即更新权重。所有 Micro-batch 的前向完成后，最后一个 Stage 才开始反向传播。反向数据沿 Stage 的逆序流动，并传递边界激活梯度。

图中采用常见的后进先出展示方式：先对最后完成前向的 Micro-batch 计算反向，再逐步处理更早的 Micro-batch。这有利于尽快释放较晚 Micro-batch 的部分状态，但具体运行时可以在不改变同步语义的前提下采用等价的合法顺序。

4.3 同步参数更新

在同一个 Pipeline Batch 内，所有 Micro-batch 的前向和反向都使用同一版本的模型参数。每个 Stage 累积本地参数梯度，直到全部 个 Micro-batch 完成后，才共同进入一次优化器更新：

6. 激活值、显存与重计算

流水线切分减少了每个 Stage 保存的参数、梯度和优化器状态，但 GPipe 的 All-Forward-All-Backward 调度会带来新的激活显存压力：一个 Stage 完成多个 Micro-batch 的前向后，必须保留反向传播所需的信息，直到相应 Micro-batch 的反向到来。

GPipe 使用 Re-materialization，也称 Activation Checkpointing 或激活重计算：

其基本过程是：

  1. 前向阶段只长期保存 Stage 输入或输出等边界激活；
  2. Stage 内部各层的中间激活在前向结束后释放；
  3. 对某个 Micro-batch 执行反向前，重新运行本 Stage 的前向；
  4. 使用重建的中间激活计算参数梯度与输入激活梯度。

重计算还必须正确处理 Dropout 等随机算子：重放前向时需要恢复一致的随机数状态，否则反向所依据的计算路径与原前向不一致。BatchNorm 等跨批次统计操作也需要特别处理，因为 Micro-batch 统计量不等于完整 Mini-batch 统计量；Transformer 中常用的 LayerNorm 通常更适合 Micro-batch 流水化。

7. Stage 之间通信什么

标准流水线并行中，模型参数长期驻留在所属 Stage，不需要在每个 Micro-batch 之间传输完整权重。相邻 Stage 主要交换：

  • 前向方向：边界激活值 ；
  • 反向方向：损失关于边界激活的梯度 ；
  • 少量控制信息：Micro-batch 标识、形状、调度事件等。

8. 模型切分与负载均衡

流水线的吞吐量由最慢 Stage 限制，因此不能简单地按层数平均切分。合理的分区需要同时考虑：

  • 每层前向与反向计算时间；
  • 参数、梯度、优化器状态和激活显存；
  • Stage 边界激活张量的通信量；
  • Embedding、LM Head、Attention 和 MLP 的计算差异；
  • 激活重计算带来的额外计算；
  • 节点内 NVLink/NVSwitch 与节点间 InfiniBand/RoCE 的带宽差异；
  • 共享或绑定参数，例如输入 Embedding 与输出 LM Head 权重绑定。

对结构规则的 Transformer，可以先按 Block 数近似均分，再通过性能时间线调整边界。Embedding、最终归一化和词表投影层经常使首尾 Stage 变重，需要减少首尾 Stage 的 Transformer Block 数。

更可靠的方法是先对每个候选模块做 Profiling，再寻找同时满足显存约束、计算均衡和边界通信较小的切分方案。优化目标不是让各 Stage 参数量相等，而是让它们的稳态节拍尽可能接近。

9. GPipe、1F1B 与异步流水线

GPipe 是流水线并行的基础方案，但不是唯一调度策略。最容易混淆的是：1F1B 只描述稳态下“一次 Forward 与一次 Backward 交替”的执行顺序，它本身并不等同于异步训练。是否异步，取决于流水线是否周期性 Flush、何时更新参数，以及不同 Micro-batch 是否允许使用不同参数版本。

9.2 GPipe：Fill-Drain

GPipe 先让 个 Micro-batch 全部完成 Forward，再按照反方向完成全部 Backward：

  1. ～ 填充并排空前向流水线；
  2. 最后一个 Micro-batch 的 Forward 完成后，最后一个 Stage 才开始 Backward；
  3. 全部 Backward 完成后，各 Stage 使用累计梯度共同进入一次 Optimizer Step。

在同一个 Pipeline Batch 内，所有 Micro-batch 使用相同的参数版本，因此没有权重陈旧问题。不过，较早完成 Forward 的 Micro-batch 需要等待较长时间才能执行 Backward，Stage 必须同时保留多个尚未反向的激活；这正是 GPipe 通常需要激活重计算的重要原因。

9.3 同步 1F1B：1F1B-Flush

同步 1F1B 先进行 Warm-up，使 Micro-batch 到达后面的 Stage。最后一个 Stage 一旦完成 ，就可以立即执行 ；随着反向依赖逐级返回，各 Stage 在条件允许时交替执行一个 Forward 和一个 Backward。最后不再注入新的 Micro-batch，将剩余 Backward 全部排空，这就是名称中的 Flush。

它与 GPipe 的关键区别是反向传播开始得更早。例如图中 GPipe 的 要到所有 Forward 之后才出现，而同步 1F1B 的最后一个 Stage 在 就开始 。这样可以更早释放对应激活，使每个 Stage 同时保留的未完成 Micro-batch 数量通常由流水线深度限制，而不再随 线性增长。

但在相同 、、Stage 均衡且不采用虚拟 Stage 的理想假设下，普通 1F1B-Flush 与 GPipe 的气泡总量和总执行时间可以相同。1F1B 的主要收益是降低峰值激活显存，而不是自动消除 Fill/Drain 气泡。一个 Pipeline Batch 仍然只在全部 Backward 完成后更新一次参数，所以它保持同步语义，也不存在权重陈旧。

9.4 PipeDream：异步 1F1B

PipeDream 采用持续的 1F1B 流，不在固定数量的 Micro-batch 之后等待整条流水线排空。图中当较早 Micro-batch 的 Backward 仍在向前传播时，、 已经进入流水线；经过一次初始 Warm-up 后，周期性 Fill/Drain 气泡便被长期摊薄。

这种做法改变了参数更新语义：某个 Stage 完成 后可以更新自己持有的参数，后续 Forward 可能立即使用新版本，而其他 Stage 仍在处理基于旧版本产生的 Micro-batch。因此，不同 Stage 或不同 Micro-batch 可能观察到不同参数版本，产生 Weight Staleness。

原始 PipeDream 使用 Weight Stashing：Stage 在执行 时保存对应的本地权重版本，到执行 时重新使用该版本，从而保证同一个 Stage 上某个 Micro-batch 的前向和反向彼此匹配。但这只能保证局部版本一致，不能让整个异步流水线恢复为同步 Mini-batch SGD。其优势是较高的稳态利用率和较低的激活压力，代价则是额外的权重版本存储、调度复杂度以及更难分析的收敛行为。

三种调度的整体差异可以归纳如下：

调度方式 稳态执行顺序 参数一致性 激活显存 主要特点
GPipe / Fill-Drain 全部 Forward，再全部 Backward 同步，无权重陈旧 较高 语义清晰、实现简单，但前后向之间保留较多激活
同步 1F1B / 1F1B-Flush 预热后交替一个 Forward、一个 Backward，末尾排空 同步，无权重陈旧 通常低于 GPipe 更早释放激活，但仍存在填充和排空气泡
Interleaved 1F1B 每个 Rank 承载多个虚拟 Stage 并交错执行 同步 依实现而定 可缩短气泡，但增加调度与通信复杂度
PipeDream 异步 1F1B 持续交替 Forward 和 Backward，不按 Pipeline Batch Flush 存在多个权重版本与陈旧性 较低 稳态利用率高，但训练语义和版本管理更复杂

Interleaved 1F1B 则是在同步 1F1B 基础上，让每个物理 Rank 承载多个不连续的虚拟 Stage，并将它们交错调度。它可以进一步缩小气泡，但会增加点对点通信次数、调度状态和实现复杂度；它仍然可以保持同步参数更新。

11. 与数据并行、张量并行组合

在大模型训练中，常用三维并行：

  • PP 组：相邻 Stage 之间传递激活与激活梯度；
  • TP 组：同一 Stage 内协作执行层内算子；
  • DP 组：复制整条 Pipeline，对相同 Stage 的参数梯度执行 AllReduce 或 ReduceScatter。

例如使用 64 张 GPU，可以采用 、、。此时一条 Pipeline 包含 4 个 Stage，每个 Stage 由 4 张 GPU 做张量并行，共 16 张 GPU；再复制 4 条 Pipeline 做数据并行。

拓扑映射通常遵循：

  1. 把通信最频繁的张量并行组放在节点内高速互连上；
  2. 流水线相邻 Stage 尽量映射到带宽较好的相邻设备或节点；
  3. 数据并行跨节点扩展，并使用高效集合通信；
  4. 结合实际激活大小、梯度大小和网络层次进行调整。

12. 如何选择流水线配置

可以按照以下顺序确定初始方案：

  1. 先满足容量约束：选择最少的 Stage 数，使每个 Stage 的参数、优化器状态、激活和通信缓冲区都能放入设备；
  2. 再平衡 Stage：根据实测前向和反向时间调整层边界，不要只按层数或参数量平均；
  3. 设置 Micro-batch 大小：先保证主要矩阵运算具有合理效率；
  4. 增加 Micro-batch 数量：在全局批次和显存允许的范围内摊薄气泡；
  5. 选择调度器：优先从语义简单的 GPipe 或同步 1F1B 开始；激活显存紧张时重点评估 1F1B；
  6. 映射物理拓扑：让 TP、PP、DP 通信组分别匹配最合适的链路；
  7. 用时间线验证：测量气泡、负载不均、通信和重计算，而不是只观察平均 GPU 利用率。

如果模型完整状态可以放入单卡，且主要目标只是提高吞吐量，DDP 通常更简单；如果模型总状态无法放入单卡，但单个层可以独立计算，PP 很有价值；如果连单层也无法放入单卡，则需要进一步引入 TP、FSDP/ZeRO 或其他分片策略。

小结

流水线并行通过“沿层切分模型、沿批次切分 Micro-batch”同时扩展模型容量和设备利用率。GPipe 将模型划分为多个连续 Stage，采用 All-Forward-All-Backward 的 Fill-Drain 调度，在一个 Pipeline Batch 结束后同步更新参数，因此没有权重陈旧问题。

理解 GPipe 的关键是把握四个量：Stage 数 、Micro-batch 数 、最慢 Stage 的节拍以及 Stage 边界的激活通信。增大 可以摊薄气泡，但会影响全局批次、算子效率、通信次数和激活管理；增加 可以容纳更大的模型，却会加深流水线并增加切分与负载均衡难度。

GPipe 提供了清晰可靠的基础语义。现代系统在此基础上发展出同步 1F1B、交错 1F1B 和更复杂的零气泡调度，但优化调度之前，仍应先保证模型切分合理、梯度语义正确、随机算子可重放，并通过真实时间线确认瓶颈。
