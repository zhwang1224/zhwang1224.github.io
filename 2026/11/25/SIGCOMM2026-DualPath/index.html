DualPath：借用 Decode 节点的存储带宽加载 KV-Cache

发表于 2026-11-25 分类于 人工智能系统 阅读时长 ≈ 15 分钟
SIGCOMM 2026 论文 DualPath 阅读笔记。Agentic 多轮推理的 KV-Cache 命中率接近 99%，瓶颈从 GPU 计算转移到 Prefill 节点的存储网卡，而 Decode 节点的存储网卡基本闲置。DualPath 增加一条“存储 → Decode → Prefill”的加载路径，借计算网络的空闲带宽把 KV-Cache 转给 Prefill，并配合 InfiniBand VL 流量隔离与负载感知调度，离线推理吞吐最高提升 1.87×，在线服务吞吐平均提升 1.96×。

DualPath（SIGCOMM 2026，北京大学、清华大学与 DeepSeek-AI）研究 Agentic 负载下 PD 分离推理的存储 I/O 瓶颈。Agent 与环境交互几十到上百轮，每轮只追加几百个 token，上下文却不断累积，KV-Cache 命中率接近 99%。每一轮要算的很少，要从外部存储读回的 KV-Cache 却很多，推理从计算受限变成了 存储 I/O 受限。

问题出在 I/O 的分布上：PD 分离架构中，命中的 KV-Cache 全部由 Prefill 节点从存储读取，Prefill 侧的存储网卡被打满，Decode 侧的却基本闲置。DualPath 增加了一条 存储 → Decode 节点 → Prefill 节点 的加载路径，由 Decode 节点读取 KV-Cache，再经带宽大得多的计算网络用 RDMA 转给 Prefill 节点，把全集群的存储网卡带宽聚合起来。离线推理吞吐最高提升 1.87×，在线服务在满足 SLO 的前提下吞吐平均提升 1.96×。

DualPath：借用 Decode 节点的存储带宽加载 KV-Cache

项目 内容
标题 DualPath: Accelerating Agentic LLM Inference by Harvesting Disaggregated KV-Cache Storage I/O
作者 Yongtong Wu、Shaoyuan Chen、Rilin Huang、Yixuan Tan、Yinmin Zhong、Mingxing Zhang、Xin Jin、Panpan Huang
机构 北京大学、清华大学、DeepSeek-AI
会议 SIGCOMM 2026
原文 DOI: 10.1145/3789240.3829159

术语：PE、DE 分别指 Prefill 引擎和 Decode 引擎，每个引擎管理一张 GPU；CNIC 为计算网卡（东西向），SNIC 为存储网卡（南北向）。

1. 背景

负载特征。 Agentic 场景中，LLM 通过终端命令、代码执行等工具与环境多轮交互：每轮输入是之前的全部上下文加上新追加的内容（多为工具输出），模型生成下一步动作，上下文最长可达百万 token。论文从代码类 Agent 任务收集的 trace 中，平均 157 轮，平均上下文 32.7k token，每轮平均只追加 429 token，KV-Cache 命中率为 98.7%。

KV-Cache 放在 SSD 存储上。 轨迹太长，基于 HBM 和 DRAM 的缓存（如 Mooncake）只能存下一小部分；RL 训练的 rollout 阶段，DRAM 还要容纳从 HBM 卸载出来的 reward 模型和优化器状态。因此 KV-Cache 放在容量更大、成本更低的外部 SSD 存储上（论文使用 DeepSeek 的 3FS）。

系统与硬件。 现有系统大多组合使用 PD 分离、Layerwise Prefill 和外部 KV-Cache 存储：PE 加载命中的 KV-Cache 并完成 Prefill，经 RDMA 传给 DE；DE 生成 token，并把新的 KV-Cache 写回存储供下一轮复用。Layerwise Prefill（LayerKV、PrefillOnly）在 HBM 中只保留当前层的 KV-Cache，batch 能容纳的 token 数扩大约层数倍。硬件以 DGX SuperPOD 为例：每节点 8 张 Hopper GPU，每张 GPU 配一块 400 Gbps 的 CNIC，每节点另有一块最高 400 Gbps 的 SNIC；计算网络与存储网络相互隔离。

2. 动机：Prefill 侧的存储网卡成为瓶颈

论文观察到 Agentic 推理中 GPU 利用率很低，原因是 KV-Cache 的加载速度受限于每个节点单块 SNIC 的带宽。这一瓶颈由三个因素共同造成。

（1）要加载的数据远多于要做的计算。 论文用 cache-compute ratio 衡量需要加载的 KV-Cache 量与所需计算量之比。追加长度为 429 时：

模型 GB/PFLOP（上下文 16K–64K）
Qwen2.5-32B（FP16） 117–267
GPT-OSS-120B 47–95
Qwen3-235B-A22B 39–60
DeepSeek-V3.2 660B 13–36
DeepSeek-V3 660B 4.8–5.8

除注明外 KV-Cache 均按 FP8 计算。即使是 KV-Cache 已被 MLA 大幅压缩的 DeepSeek-V3.2，在论文的 trace 下也约为 22 GB/PFLOP；它的比值高于 V3，原因是稀疏注意力降低了计算量。

（2）硬件演进加剧了失衡。

图 3：左为 2020–2024 年 NVIDIA GPU 的算力、网卡带宽和 HBM 容量；右为每个请求 30K 上下文、追加 300 token 时，相对 token 吞吐随 batch 大小的变化。

从 Ampere 到 Blackwell，GPU 算力增长 28.8×，PCIe 带宽只增长 2.0×，显存容量增长 2.4×，I/O 与算力之比下降了 14.4×。网卡带宽不足让 GPU 等待 KV-Cache；显存容量小又限制了 batch 大小，而右图说明 batch 足够大才能用满 GPU。

（3）存储网卡的利用严重失衡。 PD 分离中命中的 KV-Cache 只由 PE 读取，全部存储 I/O 压力集中在 PE 侧的 SNIC 上，DE 侧的 SNIC 基本闲置。给 PE 增加存储带宽成本高，在通用集群中也往往不现实。

图 1：左为现有架构，Prefill 侧存储网卡（400 Gbps/节点）打满，Decode 侧闲置；右为 DualPath，两侧的存储网卡都被利用。图中的利用率为示意。

机会。 计算网络的带宽远大于存储网络（每节点 8 × 400 Gbps 对 1 × 400 Gbps），而推理中的集合通信是亚毫秒级的突发，链路有大量空闲。因此可以让 DE 节点用自己的 SNIC 读取 KV-Cache，再借计算网络的空闲带宽转给 PE。

3. 设计

DualPath 包含三部分：推理引擎（PE 与 DE）；每个引擎内的 Traffic Manager，负责 H2D/D2H、PE 与 DE 之间的传输和存储读写；中心化的 Request Scheduler，负责分配请求并为每个请求选择加载路径。

3.1 双路径加载

图 4：(a) PE 读路径，(b) DE 读路径。粗箭头为 Full Block（包含所有层），细箭头为 Layer Block（单层），数字为数据流的步骤。

每个 PE 和 DE 预留少量 DRAM 作为缓冲区（PE buffer、DE buffer）。

  • PE 读路径：命中的 KV-Cache 经 PE 节点的 SNIC 读入 PE buffer（1–2）；每层计算前把该层 KV-Cache 拷入 PE 的 HBM（3–4），计算未命中 token 的 KV-Cache；再把该层全部 KV-Cache 经计算网络传到 DE buffer（5–7）。3–7 逐层重复，与计算重叠。
  • DE 读路径：命中的 KV-Cache 经 DE 节点的 SNIC 读入 DE buffer（1–2）；PE 做 Prefill 时逐层从 DE buffer 经计算网络读入 HBM（3–5）。每层算完后，PE 只把未命中 token 的 KV-Cache 传回 DE buffer。
  • Decode：DE buffer 中凑齐完整的 prompt KV-Cache 后，DE 分配 HBM 并做 H2D，再释放 DRAM。不用 GPUDirect RDMA 直接写 HBM，论文给出的理由是减少 HBM 占用：Agentic 场景生成长度短，TTFT 在请求总时长中占比不可忽略。Decode 期间每攒满一个 block（如 64 token）就写回存储。

与存储交互统一用 Full Block，逐层传输用 Layer Block；n 个 Layer Block 拼起来即为一个 Full Block，无需转换内存布局。

3.3 以 CNIC 为中心的流量隔离

额外的 KV-Cache 流量会与 EP AllToAll 等对延迟敏感的集合通信争抢计算网络和 PCIe。GPUDirect Storage 和 CUDA copy engine 不受计算网络 QoS 的控制，GPU 也不支持 PCIe QoS，而集合通信是亚毫秒级的突发，软件整形难以奏效。DualPath 因此让 所有进出 GPU 的数据都经过与之配对的 CNIC：

  • VL 隔离：模型推理通信走高优先级的 InfiniBand VL，KV-Cache 等其余流量走低优先级 VL；VL 仲裁器按加权轮询为高优先级保留约 99.9% 的带宽。RoCE 网络可以用 IEEE 802.1Q PCP 实现同样的隔离。
  • CNIC 辅助的 H2D/D2H：KV-Cache 先从存储读到主机 DRAM，再提交 RDMA Write 由 CNIC 写入本机 GPU，写回方向对称，CNIC 由此成为 GPU 全部 PCIe 流量的 QoS 调度点。附带的好处是提交开销低：cudaMemcpyAsync 每次约 5–7 μs，RDMA Write 约 1 μs，还能用 doorbell batching 摊薄，适合 Layerwise Prefill 产生的大量小块。

微基准中，EP16 下每个端口加入 20 GB/s 的低优先级背景流量，DeepEP dispatch 延迟从 131 μs 升至 877 μs（6.7×）；开启 VL 隔离后为 141 μs。

3.4 调度

两条路径都可用之后，调度要同时平衡 GPU 和网卡，否则会压垮其中一条路径。GPU、磁盘和网络的负载都与 token 数强相关，调度器以 token 数作为统一的负载指标，分两级：

  • 引擎间调度：引擎按组拉取请求，上报未完成的 token 数 tok_e 和所在节点的磁盘读队列长度。选 PE 时跳过 tok_e 超过 β 的过载引擎，优先选读队列短（不超过 α）的节点，避免其 SNIC 空闲，同类中选 tok_e 最小者；α、β 分别取 3 秒内能读完、单张 GPU 5 秒内能处理的 token 数。DE 按组间、组内两级平衡 token 数与剩余 HBM。PE 和 DE 确定后，从读队列较短的一侧读取 KV-Cache。
  • 引擎内调度（仅 PE）：attention 采用数据并行时，各 GPU 的 attention 结束后要同步进入 FFN，耗时不均会产生等待气泡。DualPath 为每次 forward 设置 compute quota（300 ms），按 FIFO 加入请求并预测 attention 耗时，超出时二分查找能放下的长度，对该请求做 chunked prefill。

4. 实验结果

设置。DualPath 基于 DeepSeek 的内部推理框架实现，改动约 5K 行。每节点 8 张 Hopper GPU、8 块 400 Gbps 的 InfiniBand CNIC，另有 1 块 SNIC 接入 3FS（无 DRAM 缓存，可打满 400 Gbps）。模型为 DeepSeek-V3.2 660B（DS 660B）、其 27B 缩小版（DS 27B）和 Qwen2.5-32B（Qwen 32B），默认配比分别为 2P4D、1P1D、1P2D（2P4D 即 2 个 Prefill 节点、4 个 Decode 节点）。trace 来自生产环境的 Agentic RL 训练任务，每组 500 条轨迹：

MaxLen 平均轮数 每轮追加 每轮生成 总 token 上下文 token
32K 60 608 148 28639 17183
48K 106 474 172 42607 25120
64K 157 429 176 55958 32721

基线：Basic 为未修改的内部框架；Oracle 跳过所有磁盘读取、H2D/D2H 和 PD 之间的传输，代表零 I/O 开销的上界；SGL(MC) 为 SGLang + HiCache + Mooncake Store。由于实现差异，论文只报告相对 Basic 的提升。

4.1 离线批量推理

离线场景对应 RL 训练的 rollout：一批 Agent 同时开始执行，指标为全部完成所需的时间（JCT）。

图 7：上、中、下三行分别为 DS 27B、DS 660B、Qwen 32B，三列为最大 Agent 长度（MAL）32K、48K、64K；N/A 表示 SGL(MC) 运行出错。

  • DS 660B 相对 Basic 最高提速 1.87×，并接近 Oracle，KV-Cache 的 I/O 开销基本被消除。
  • DS 27B 最高提速 1.78×，但比 Oracle 慢 1.09–1.85×：1P1D 只有两块 SNIC，存储带宽仍然不够。Qwen 32B 的趋势类似。
  • Agent 越多、MAL 越长，收益越大；把每轮追加长度缩放到 1–3 倍，提速保持在 1.82–1.99×。

图 8：DS 27B 在三种配比下的离线 JCT；纯色、点状、斜线分别对应 1P1D、1P2D、2P1D。

不同配比下平均提速 1.64×，最高 2.46×。更值得注意的是三组性能相当的配置：Basic 1P1D 与 Basic 1P2D、DualPath 1P1D 与 Basic 2P1D、DualPath 2P1D 与 DualPath 1P2D。每组可用的存储带宽相同（Basic 只能用 Prefill 节点的 SNIC，DualPath 能用所有节点的），说明存储带宽是 Agentic 场景的主要瓶颈。

4.2 在线服务

Agent 按 Poisson 过程到达并重放整条轨迹，SLO 为 TTFT ≤ 4 s、TPOT ≤ 50 ms。

图 10：横轴为每秒到达的 Agent 数（APS），上为 DS 27B，下为 DS 660B；TTST 与 TPOT 图中超过 SLO 的点未画出。

满足 SLO 的最大 APS，DS 27B 为 Basic 的 1.67×，DS 660B 为 2.25×，平均 1.96×。TTST 与 Basic 相当，TPOT 没有增加，借用计算网络没有拖慢 Decode。TTFT 分解（图 12 左）显示，Basic 的排队时间随 APS 增加而急剧上升，DualPath 的 TTFT 构成基本稳定。

5. 总结与思考

1. 瓶颈从计算转向 I/O，并且还在加剧。 命中率接近 99% 时，每轮的主要开销是把 KV-Cache 读回来。稀疏注意力降低了计算量，DeepSeek-V3.2 的 cache-compute ratio 反而高于 V3；GPU 算力的增长又远快于 PCIe 和网卡。Mooncake 用分布式 DRAM 池解决命中率问题，DualPath 面对的是命中之后的带宽问题：KV-Cache 放在 SSD 上，DeepSeek 模型每节点只分配 80 GB DRAM（SGL(MC) 为 1.5 TB）。

2. 瓶颈不在总带宽，而在带宽归谁使用。 P/D 配比实验中，性能只取决于能用上的 SNIC 数量，Basic 增加 Decode 节点几乎没有帮助。PD 分离按计算特征拆分 GPU 的同时，也把存储 I/O 绑在了 Prefill 节点上；DualPath 解开的是这层绑定，把存储带宽变成全集群可调度的资源。

3. 经由 Decode 读取并不是绕远路。 命中的 KV-Cache 最终既要进入 PE 的 HBM 做 Prefill，也要进入 DE 的 HBM 做 Decode。按图 4，PE 读路径搬运四次（存储 → PE DRAM → PE HBM → DE DRAM → DE HBM），DE 读路径只要三次（存储 → DE DRAM，再分别送往 PE HBM 和 DE HBM），PE 只回传少量未命中 token 的 KV。计算网络上的数据量基本不变，只是命中部分改走原本很空的 DE → PE 方向。代价是负载集中到 DE 节点的 DRAM 和 CNIC 上，所以无瓶颈条件的三个上界都来自 DE 侧。

4. 数据路径由 QoS 的位置决定。 GPU 的 PCIe 没有 QoS，能做硬件仲裁的只剩计算网卡，所以 DualPath 放弃了更直接的 GPUDirect Storage 和 CUDA copy engine，连本机的 H2D/D2H 也经由 CNIC 完成。存储网络与计算网络在物理上仍然分开，但来自存储的流量进入了计算网络，靠 VL 优先级实现逻辑隔离；没有这层隔离，DeepEP dispatch 延迟会变为原来的 6.7 倍。
